## When to Use
When the user wants their own outstanding review feedback handled across their onshape-org repos in one shot: find every open PR they authored in the `onshape` org that has unresolved review threads, then fan out one autonomous subagent per PR to fix and close the threads. PRs in personal repos (e.g. ethanrous/*) are deliberately OUT of scope for this sweep. NOT for interactively working through a single PR's comments in the current checkout (use resolve-pr-comments directly) and NOT for failing CI on a PR (use fixing-pr-checks). Requires gh auth and the standing convention that every relevant repo is checked out under ~/repos/.

## Procedure
1. Preflight: `gh auth status` must succeed. All repos live in ~/repos/ — if a discovered PR belongs to a repo not present there, do not guess or clone blindly; list it in the final report and ask.
2. Discover every open PR I authored in the onshape org in ONE call: `gh search prs --author "@me" --state open --owner onshape --json number,title,url,repository` (the `--owner onshape` qualifier scopes the search to onshape-org repos; as a belt-and-braces guard, also drop client-side any row whose `repository.nameWithOwner` does not start with `onshape/`). PRs in personal repos are intentionally out of scope for this sweep — if the user specifically asks about one, offer to run resolve-pr-comments directly on that PR instead. Note: `headRefName` is NOT a valid field for `gh search prs` — branch names come from the per-PR probe in the next step.
3. Per candidate PR, run ONE GraphQL probe that both gates dispatch and supplies branch names (parse OWNER/NAME from the PR url .../owner/repo/pull/N): `gh api graphql -f query='query($owner:String!,$repo:String!,$n:Int!){repository(owner:$owner,name:$repo){pullRequest(number:$n){state headRefName baseRefName reviewThreads(first:100){nodes{id isResolved isOutdated}}}}}' -F owner=$OWNER -F repo=$NAME -F n=$N`. Dispatch ONLY PRs with >=1 thread where isResolved==false AND isOutdated==false (filter client-side with jq — the API rejects a `states:` argument on reviewThreads). Outdated-only threads do not justify a spawn.
4. Show the user the dispatch list (repo, PR #, title, open-thread count), then spawn one subagent per PR — ALL Agent calls in a single message, every one run_in_background:true. Use sonnet-5.5 subagents with xhigh thinking for all dispatches — user preference for this sweep: code is pushed publicly under the user's account, so quality outranks cost. Tell each subagent explicitly not to delegate further.
5. Each subagent prompt must be self-contained (fresh context). Include: repo path `~/repos/{repo}`; PR number, URL, headRefName, baseRefName; and this contract verbatim: (a) 'You are running the resolve-pr-comments skill in autonomous sweep mode. Read ~/.claude/skills/resolve-pr-comments/SKILL.md first and follow its mapping/categorization steps exactly. Its interactive approval gates do NOT apply here — the user invoked this sweep as standing approval for Categories A and B. Do not pause to ask.' (b) 'Do ALL work in a worktree, never the main checkout: `git fetch origin && git worktree add ~/.worktrees/{repo}/{headRefName} origin/{headRefName}`, then work from ~/.worktrees/{repo}/{headRefName}/.' (c) 'Category A (already fixed): reply acknowledging the fix, then resolve the thread. Category B (valid): make the minimal fix, follow project conventions, run the project's lint/tests, commit locally (no co-author trailer), push to origin {headRefName}, then reply describing the fix and resolve the thread.' (d) 'Categories C (disagree) and D (question/discussion): leave COMPLETELY untouched — no reply, no resolution. Collect them for the report.' (e) 'Never force-push. If origin/{headRefName} advanced after your fetch, re-fetch, integrate, re-verify line anchors before posting any reply, and skip resolving any thread whose anchor you can no longer trust.' (f) Return: per-thread disposition table (file:line, category, action taken, reply posted), pushed commit SHAs, C/D items needing human judgment, anomalies.
6. On each completion notification (never poll): trust but verify — confirm the pushed commit exists on origin/{headRefName} (`gh pr view {n} --json headRefOid`) and re-run the GraphQL probe to confirm only legitimate C/D threads remain open. Resume dead subagents (Agent resume) or finish their remaining threads yourself.
7. Clean up: `git worktree remove ~/.worktrees/{repo}/{branch}` for every processed PR; `git worktree list` must show nothing left behind in the affected repos.
8. Final digest to the user: one block per PR (what was fixed, pushed, resolved) plus a consolidated 'needs you' list — every C/D thread with your reasoning and the PR link.

## Pitfalls
- Scope is onshape-org only, by design: personal-repo PRs (e.g. ethanrous/weblens) are excluded from the sweep even though `--author "@me"` would match them. Do not widen the scope on your own — if the user wants a personal repo handled, say the sweep excludes it and run resolve-pr-comments directly on that PR with explicit approval.
- Never mutate the main checkouts in ~/repos — they are shared and actively used. Every edit, commit, and push originates from the ~/.worktrees/{repo}/{branch}/ worktree. This is why the inner skill's 'Do not create git commits' rule is relaxed here: local commits in a throwaway worktree are expected; the public act (the push) is what the user pre-approved by invoking the sweep.
- REST `/repos/O/R/pulls/N/comments` returns ALL comments including resolved ones and has no thread IDs — use the GraphQL probe for gating and let the inner skill handle thread-ID matching for replies/resolves.
- One subagent per PR; never two against the same repo+branch. Dedupe on (repo, PR number) before fanning out.
- When unsure whether a thread is Category B or C, classify it C: an extra thread left open for the user to glance at is far cheaper than wrongly resolving a thread they disagree with.
- If gh reports a PR's repo is not in ~/repos, do not silently clone an arbitrary remote — report it and ask.
- The user's own comments and review summaries are not feedback — the subagent must categorize from the REVIEWER's perspective and never 'resolve' a thread by replying to itself.

## Verification
1. No subagent was dispatched for any PR outside the onshape org; personal-repo PRs, if present in the raw search output, appear in the final report only as out-of-scope.
2. Re-running the GraphQL probe on every dispatched PR shows zero unresolved non-outdated threads among those categorized A/B; only the reported C/D threads remain open.
3. `gh pr view {n} --json headRefOid` matches the latest commit the subagent reported pushing.
4. `gh api repos/O/R/pulls/N/comments` filtered to the user's login shows the new replies sitting in the resolved threads.
5. `git worktree list` in each affected repo shows no leftover entries under ~/.worktrees.
6. The user received the per-PR digest including the 'needs you' list (which may legitimately be empty).
