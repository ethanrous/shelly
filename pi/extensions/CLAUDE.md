# pi extensions

Local pi extensions, symlinked to `~/.pi/agent/extensions/`. pi auto-discovers `*.ts` here, so adding one needs no setup-script or `settings.json` change.

`thinking-stats.ts`, `keep-chat-on-compaction.ts`, and `model-search.ts` patch pi internals, so a pi upgrade can silently disable them; the fallback is pi's stock behavior. The repo has no `node_modules`, so editor diagnostics about unresolved `@earendil-works/*` imports are expected; pi resolves them at load time. Apply edits with `/reload` in pi.

- `thinking-stats.ts` - puts a spinner, elapsed time, and token count on the collapsed thinking label (`Thinking... 42.1s (1.3k tokens)`, then `Thought for 11.2s (756 tokens)`). It wraps `AssistantMessageComponent.prototype.updateContent` and sets `hiddenThinkingLabel` per component. The `pi-thinking-tail` package replaces the same method outright, so the wrapper is re-installed on `session_start` to stay outermost.
- `keep-chat-on-compaction.ts` - keeps the full rendered chat on screen across compactions; only the model context is compacted. It wraps `InteractiveMode.prototype.handleEvent` and, for a successful `compaction_end`, turns `chatContainer.clear` and `renderSessionEntries` into no-ops for that one call, so pi only appends the `[compaction]` block. `/reload`, `/resume`, and tree navigation still rebuild the chat from the compacted context.
- `model-search.ts` - replaces `ModelSelectorComponent.prototype.filterModels` so `/model` search matches each whitespace-separated token as a case-insensitive substring of `provider/id name`, instead of pi's fuzzy subsequence match (which matched "opus" inside `github-copilot/gpt-6-sol`). Matches are sorted newest first by the numbers in the model id (`opus-5.5` > `opus-5` > `opus-4.8`), since pi's `Model` has no release date. An empty query keeps pi's order.
- `copilot-usage.ts` - status-bar item (`Copilot: +312 session · 22.6k/40k (56%) · resets Oct 1`) shown only while the selected model's provider is `github-copilot`. Reads the OAuth token from `~/.pi/agent/auth.json` and calls `GET api.github.com/copilot_internal/user`; the session figure is the change in `credits_used` since the first fetch of the session, so concurrent Copilot use elsewhere on the account counts too. Refreshes 3s after each turn and every 5 min; `/copilot-usage` forces one.
- `json-string-args.ts` - on the assistant's `message_end`, before pi validates tool calls, parses string arguments that hold JSON where the tool schema expects an array or object (recursing into properties and items; a schema that also accepts a string is left alone). The vLLM qwen3_xml parser can deliver an array parameter such as `ask_user_question.questions` as JSON text; pi's coercion only handles primitives, and TypeBox then wraps the string in an array (`questions.0: must be object`). Returning a replacement from `message_end` mutates the message in place, so tool execution sees the fixed arguments. Applies to every provider.
- `lucy-flat-edit.ts` - for the `lucy`/`lucy-vllm` providers only, rewrites the `edit` tool in the outgoing request (`before_provider_request`) to a flat `{path, oldText, newText}` schema and rewords the system prompt's `edits[]` guidance. The vLLM qwen3_xml parser passes an array parameter through as hand-written JSON text, which the 27B breaks on long payloads; string parameters skip that step. pi's built-in edit tool converts the flat shape back to `edits` before validation, so nothing changes for other models. `/lucy-strict` toggles `strict: true` on that tool (off by default) to test whether the server enforces the schema with structured outputs.
- `trim-cwd-noise.ts` - on the `context` event, rewrites the copy of past tool calls sent to the provider: drops a leading `cd <cwd> &&`/`;` from bash commands, and makes absolute or `~` paths inside the cwd relative on `read`/`write`/`edit`/`grep`/`find`/`ls` calls. The persisted session and the executed calls are unchanged. A `cd` to anywhere but the exact cwd, and a path outside the cwd, are left alone.
- `instruction-files.ts` - injects glob-gated instruction files into the system prompt as the session touches matching files. pi's stock loader only recognizes AGENTS.md/CLAUDE.md and never parses frontmatter, so it walks a global root (`~/.pi/agent/instructions/`, synced from the repo's `pi/instructions/`) plus cwd and every ancestor (like pi's own AGENTS.md inheritance, deepest scope first), collects the markdown under each `.github/instructions/`, and reads each file's `applyTo:` directive (bare/quoted scalars, comma lists, `[a, b]`, and YAML block lists). Files without a directive apply unconditionally from turn one; gated files land from the turn after the first `read`/`edit`/`write`-style tool call on a matching path — globs are gitignore-flavored (`**` spans zero or more directories; a pattern with no `/` matches the basename at any depth). Matches are appended to `systemPromptOptions.contextFiles`, so they render as `<project_instructions path="...">` blocks exactly like AGENTS.md. The global root currently holds three files: `code-comments.instructions.md` (`applyTo: "*"` — cross-language comment rules that load as soon as *any* file is touched), `python-conventions.instructions.md` (`**/*.py`), and `markdown.instructions.md` (`**/*.md`). Touched paths come from `tool_call` events (absolute, `~/`, or cwd-relative), and steady turns only re-stat the instruction files — content is re-read solely when one changed. Matching against touched paths instead of the whole repo is what keeps a monorepo-root session cheap: in data-insights a fresh session costs 0 tokens, touching a library `.py` adds ~3k, and a portal+justfile session totals ~9k, versus ~89k if every instruction file loaded up front.
- `targeted-compaction/` - scores redundant/bulky/stale context items (superseded reads, duplicate outputs, failed-then-retried calls, old bulky tool output, old thinking blocks) while the model works, then prunes them into one-line stubs in a single batch once context usage crosses a threshold, so pi-blackhole's summarizing compaction is delayed and each flush costs exactly one cache-miss reprefill. Config lives under `targetedCompaction` in `models.json` (enabled on `lucy`); see `targeted-compaction/README.md` for the full design, an optional `laya` sidecar scorer, and `/prune`.
